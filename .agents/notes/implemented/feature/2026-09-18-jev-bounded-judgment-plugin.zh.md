# Agent Note: Jev 有界判断插件

Status: implemented

[English](2026-09-18-jev-bounded-judgment-plugin.md) | 中文

## Problem

DSH 会在任务的每一步都使用当前最强的模型，向每个请求暴露全部已注册工具，并用静态规则表达权限策略。这三者其实都是有界判断——用哪个模型、用哪些工具、执行还是确认——但目前的代价分别是一次通用模型调用，或是一条无法表达上下文的全局规则。

产品需要的是一个比询问 LLM 更快、更便宜的判断层：为某一步选择模型，从请求中剪掉明显无关的工具，并根据用户自己的自主偏好判断一个拟执行动作。它不能变成第二个 Agent 循环，而且在它缺席时，DSH 必须与今天完全一致。

## Decision

`@deepseek-ai/dsh-jev` 提供一个可选插件，包含三项可独立开关的能力，每项都挂在既有扩展点上：

| 能力 | 接入点 |
|---|---|
| 模型路由 | 每个 Agent 的 `installModelSelection` + `agent/pre-step` |
| 工具预过滤 | `system-prompt/assemble` 瀑布，且在 `next()` 之后 |
| 权限层 | `tools/pre-execute` 瀑布，只收紧 |

这三个判断是 `JevProvider` 接口背后的纯函数（`routeModel`、`selectTools`、`judgePermission`）。默认 provider 是确定性的、无依赖的，这使插件在没有凭据、没有网络时依然可用且可测；`provider: remote` 增加一个 HTTP 后端，带有文档化的 JSON 契约、在传输边界处的响应校验、超时，以及在任意失败时回退到确定性实现。

路由按委派深度对步骤分类：顶层 Agent 负责编排，被委派的子 Agent 负责执行。这直接对应模型分配的工作流——用强模型做拆解，用高效模型做已明确规定的子任务——而不必从消息文本猜测任务语义。偏好是自然语言，解析为按角色绑定的有序规则，同分时由配置的 bias 决定。

工具预过滤在其他所有提示贡献者之后运行，因此只能收窄最终集合，并且在任何出错代价较高的情形下都不裁剪：工具太少、没有可见的任务文本、没有匹配、低于保留下限，或删除比例超过配置。目录中大多数工具本就共有的词不携带信号。

权限判断先委派给整条下游决策链，之后只能让结论更严格：allow 可以变成 ask 或 deny，而 deny 绝不会被放宽。因此 Jev 调整自主程度的同时，DSH 的强制约束效力完整保留。三个 profile（`conservative`、`balanced`、`autonomous`）在可配置的风险规则之上定义固定阈值，“直接拒绝”通过把某条规则提升为 `critical` 主动选择。

决策发布在实时的 `jev/decision` 事件与插件日志上。没有新增 Jev 专有的会话事件：`request/header` 已经记录了被路由的模型与暴露的工具 schema，`approval/asked` 记录了权限原因，因此每个对模型可见的后果都能从日志重建，而无需扩大会话词汇。

## Testing

包内测试既直接覆盖判断核心，也通过真实 Agent 循环配合脚本化 mock adapter 覆盖三项能力：顶层 Agent 与 `delegationDepth: 1` 子 Agent 的角色分类、常规步骤路由、显式路由/偏好/排除模式的优先级、过滤器的保留下限与“有区分度词项”规则、子句优先级、profile 阈值、ask→回答者→批准后执行这条路径及其持久的 `approval/asked` 原因，以及“下游 deny 或 ask 绝不被放宽”的权限边界。加载期报错的配置既在 `resolveConfig` 层覆盖，也通过插件加载覆盖。

测试策略所要求的装配级免密钥快照是本变更记录在案的覆盖缺口：快照工具回放的是录制好的 provider 流量，而录制一份能够触发 Jev 的会话需要当前环境并不具备的 provider 凭据。在该 fixture 录制完成之前，脚本化 adapter 的循环测试是最强的可用证据，而这份快照必须与首次具备密钥时所做的改动一同提交。

## Alternatives considered

**拆成四个包（服务定义、路由、预过滤、权限）。** 在 roles 独立演进时，seam 原则要求拆分。但这三个消费者共享同一套配置面、同一个后端与同一套判断词汇，且 PRD 将它们界定为一个插件；拆分只会增加三个包边界与三行配置，却没有独立的归属方。服务本身仍以 `ctx.jev` 暴露给未来的消费者。

**从消息内容重新分类角色。** 读取已领取的消息能让回合的第一步路由得更准确，但 `agent/pre-step` 在提示装配之后运行，此时新提示尚未写入日志，判断会晚一步生效。委派深度在创建时即可获得、是确定性的，并且能从会话头重建。

**在 `agent/pre-step` 内部调用 provider 来过滤工具。** 预过滤必须观察到任务，而 pre-step 是第一个能看到已领取消息的钩子——但装配已经发生，因此过滤总会晚一步。装配期过滤配合第一步保守地不动作，既更早也更安全。

**把 Jev 决策记录为会话事件。** 持久化已由 `request/header` 与 `approval/asked` 满足。新增会话事件需要扩展可合并的事件映射、重新生成持久化目录，并为旧版本把事件标记为可忽略——这带来成本，却对重建毫无增益，因为每个对模型可见的效果其理由都已经是持久的。

**默认硬拒绝高危动作。** 默认的 `critical` 规则会在所有 profile 下拒绝正当工作（例如写入 `.env` 文件）。拒绝保持为主动选择，因此交付的默认值绝不会静默破坏任务。

## Consequences

Jev 可以在不改变 Agent 循环的前提下降低成本与上下文，而省略或禁用它部署不受影响。插件不添加任何提示文本，因此它对模型可见的影响只有被路由的模型与暴露的工具 schema——两者本来就在请求头中。

代价是要维持四组启发式判断的诚实性。角色分类除委派深度外看不到任务内容；工具相关性是词法的，因此近义词会被保留而非匹配；权限文本按关键词多数匹配，因此用词意外时会退回到 profile 与风险规则。保守的默认值选择“多暴露一个工具、多请求一次确认”，而不是“剪掉必需工具、漏掉警告”。
